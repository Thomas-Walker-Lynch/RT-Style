Scope

This document is the one authority on how RT names things: identifiers in every programming language, files and directories, projects, namespaces, commands, and the names a program gives to things on a system. The other RT and Harmony documents hold only what is particular to their context, and refer here for the rest.

Names are made of words, and words are grouped into components. The rules below say how words and components are separated, how they are capitalized, and what happens when a language or a system does not accept a separator. Much existing code and many existing files predate these rules. A name that does not conform is updated when work brings us to it.

Separator

The separator ladder

Each separator binds more loosely than the one before it:

  • - joins the words of one component.
  • _ joins the components of a compound.
  • ·, the middle dot, separates the levels of a namespace.
  • . adds a property to a file name, for the tools that process the file. In program text the dot belongs to the language.

In rounded_x-coordinate there are two components, rounded and x-coordinate, and the second has two words. The hyphen binds x to coordinate more tightly than the underscore binds either to rounded. Which grouping is meant decides which separator goes where: city-scape_building-height is the building height of a city scape.

Spaces are not used in names.

Demotion

Many languages do not accept - in an identifier: C, Python, Java, the shell, and SQL without quoting among them. There the ladder moves down one step, and each separator keeps its meaning:

  • each _ becomes __, then
  • each - becomes _.

So rounded_x-coordinate is written rounded__x_coordinate. The order of the two steps matters: done the other way round, the underscores made from hyphens would be doubled too. The rule is reversible. To read a demoted name, take each __ back to _, and each remaining _ back to -.

Demotion applies to every identifier in such a language, not only to names that came from elsewhere. That is what makes it reversible: in a C or Python identifier a single underscore always joins words, and a double underscore always joins components. A predicate has_right-neighbor in Lisp is has__right_neighbor in Python, and a path variable dirpa_root is dirpa__root.

A name never begins with a separator. That keeps clear of the names C reserves, those beginning with __ or with _ and a capital letter, and of Python, which treats a leading __ as a request for name mangling. Python's other special names, such as __init__, are the language's own and keep their form. C++ reserves every identifier that contains __ anywhere; RT code is not written in C++, and a C++ project would need its own exception.

A variable that passes through the process environment takes the demoted form, since the shell will not accept a hyphen in a variable name, even when the language that sets it would.

Component order

As long as it is sensible and does not break a parallel construction, the broadest category or the least changing component goes on the left, and each component after it narrows the meaning. A conditional write function is write-conditional, not conditional-write, because it is a refinement in the general category of write functions.

Word or component

Words that together name one thing are one component. A boundary between components falls where the name steps from one thing to another: from a kind to what is of that kind, from an owner to what it owns, from a category to the member or the operation within it. With so fine a hierarchy some names can be read two ways. These readings settle most of them:

  • A phrase is one component: a verb and its object, as install-gate; an adjective and its noun, as system-account; a compound noun, as publication-count, gate-path and tree-dir.
  • A prefix that gives a type, a container or a predicate is a component of its own: list_problem, map_type, set_key, is_absent, has_result. So is a type or container given as a suffix: work_dpath, uid_set.
  • When one part of a name is itself a phrase, the boundary beside it is a component boundary: system-account_name is the name of a system account, and parent_database-uid is the database uid of a parent. A two word compound has no such part, and stays one component: storage-name.
  • A modifier that stands outside a compound is a component: rounded_x-coordinate, free_system-uid, display-name_max.
  • A category followed by the operation on it, or by the member of it, is two components: storage_make, system-account_delete, state_idle, format_open.

Where a name still reads two ways, the author picks one, and a later reader who sees it differently changes it.

Case

  • Types, modules, classes, interfaces and namespaces: PascalCase.
  • Functions and variables: snake-kebab_case, lower case words joined by the ladder, as rounded_x-coordinate; demoted, rounded__x_coordinate.
  • Globals and constants: the same in capitals, as MAX_RETRY-COUNT; demoted, MAX__RETRY_COUNT.

PascalCase joins the words of a component by capital letters rather than by a separator, so demotion leaves it unchanged. Its components are still joined by _, as in any other name, and that underscore is demoted to __.

Proper noun and acronym

A proper noun names one particular thing: a person, a product, a project, a standard. Whether its words describe the thing does not matter. Emacs, Ariadne, the Golden Gate Bridge and Account-Tree are all proper nouns.

A proper noun has one written form, chosen by whoever named the thing, and keeps it in every case style, including its capitalization. Acronyms keep their capitals. Pseudo-acronyms keep the casing given them, as SubU does. So a count of publications from the IEEE is IEEE_publication-count, demoted IEEE__publication_count.

The words of a multi-word proper noun are joined by -: Man-In-Grey, Account-Tree, RT-Style, GNU-Emacs. Where the hyphen is not accepted, the name is demoted by the rule above, and nowhere else is it spelled differently: Man_In_Grey.

In a name with other components, a proper noun is a component of its own, joined to the rest by _, even when it is one word. In a namespace that groups variables of GNU Emacs, GNU-EmacsVariables would suggest that EmacsVariables binds more tightly than GNU-Emacs; the name is GNU-Emacs_Variables, demoted GNU_Emacs__Variables. Likewise Emacs_Variables, not EmacsVariables. One rule then covers every proper noun, a reader sees where the name ends, and a tool can find the proper noun by its boundary without a list of proper nouns.

Project name

A project name is a proper noun. It is written as chosen, with hyphens between its words, in prose, as the name of the project's directory and repository, in document and file names, and in command names. Where the project's name must be an identifier, it takes the demoted form:

  • Man-In-Grey the project; Man_In_Grey its namespace and Python module.
  • Account-Tree the project; Account_Tree its namespace.

An external registry with naming rules of its own, such as a distribution's package names, which are lower case, gets a form made from the project name by a fixed rule, used only in that registry.

Namespace

In a language without native namespaces, the middle dot separates the levels of an ad hoc namespace within an identifier: Math·rounded__x_coordinate is a variable in the Math namespace, or a function on the Math interface. Most parsers accept the middle dot in identifiers.

A namespace is named in PascalCase, with a proper noun as a component of its own. A namespace for the gates of Man-In-Grey is Man-In-Grey_Gate, demoted Man_In_Grey__Gate, and the function run of its Gate module is Man_In_Grey__Gate·Gate·run in C.

A namespace's name is read by languages: it becomes the prefix of C macros and of the names of importable modules. So wherever it appears, in a directory name, a file name or code, it is written in its demoted form if any language that reads it does not accept the hyphen.

A file that holds a namespace's main module is named for the namespace alone, as Guard.py. A file specific to a namespace carries the namespace's name before a middle dot, as Guard·WellFormed.py. An application's files parallel these inside its own namespace, as Emplace_Bio·Guard.py.

File and directory name

File system names follow the identifier rules. The file system accepts the hyphen, so file and directory names use snake-kebab_case, undemoted, as how-to_add-project-dependency.html and single-file_C-module-and-namespace.html do. The exception is a name some language reads as an identifier, which takes the demoted form:

  • a Python module meant to be imported, since import needs an identifier;
  • a source file whose base name becomes a macro or a symbol, such as a C library module;
  • a directory named for a namespace.

A file that holds one class or module carries the class's or module's name. A file holding a primary class and auxiliary ones carries the primary class's name.

A directory gives each file in it a property, and its name names that property, in the singular, as an identifier does: who uses the files, the role of the people who use them, the program they belong to, or the kind of thing they are. Harmony's developer, tester, authored and made are named this way. A directory that is a package or a namespace follows the namespace rules.

A dot suffix gives a file a further property, telling the tools how the file is to be processed. A file can carry more than one, as Math.lib.c does. The suffixes a particular build uses are listed with that build, for Harmony in naming_file-and-directory.html.

Command name

A command is named as a function is, and its name is a file name, so it takes the hyphen: Account-Tree_admin, new-project, skeleton_diff. A command written in Python that is also imported as a module takes the demoted form, since import needs an identifier; a file with a hyphen in its name can still be loaded by path.

Name on a system

A program gives names to things on the systems it runs on: accounts, directories, devices, service units, configuration files. These follow the file and identifier rules as far as the system allows. Where a system gives a character a meaning of its own, the system's rule wins; systemd, for one, reads a - in a unit name made from a path as a /, and writes a literal hyphen there as \x2d.

A name a program has already given out on systems and on storage is data other things depend on: a directory holding files, a mark by which the program recognizes its own files, a string that feeds a hash. Changing such a name needs a migration of what already exists, and is decided name by name.

Name in data

A name that is only ever a string follows the rule of where it is written. A word on a command line, a tag at the head of a line of output, a flag a program prints: each of these accepts the hyphen, and takes it, as check-only, constraint-broken and uid-differ do.

A name in data that some language reads as an identifier takes the demoted form. The table and column names of a database are identifiers of SQL. The names an instruction language defines, its types, formats, variables and operation specifiers, are identifiers of that language, and many are also names in the code that implements it, so they are written as that code writes them: list__instruction, format__open.

Convention dictated from outside

Where a library, a kernel interface, a file format or a protocol fixes a name, we use the name as it is fixed, since nothing else will work. A call to a library function named incrementCount is written incrementCount, though we use camel case nowhere ourselves; a kernel constant keeps the kernel's spelling, and a structure's fields keep the names its definition gives them.

We do not wrap such a name in a gasket, a function of our own whose only work is to give the outside name a conforming one. A gasket is written when the outside name cannot be used as it stands, because the code would not function or because the name is confusing enough to mislead a person reading the code.

Abbreviation

Outer scope identifiers are spelled out for clarity, as in Lisp programming culture. That lets people who are not in the club start reading the code, and tends to make it self documenting. File system names mirror the identifier rules, so names such as library and source are spelled out.

For long words, inner scope identifiers, temporary variables and conventional suffixes, abbreviations become more common. By the time we reach the variables of an inner loop, such as a loop counter, a name is typically one letter long.

The term make

When the language allows it, a factory function is called make. It is not called create, nor new. The same holds for commands that produce things.

Container and type prefix

The name of a container is not made plural. Instead, the container's abstract type or actual type is put before the name as a component of its own. Recall that types are PascalCase.

  • list_* / seq_* : generic ordered items / indexed items
  • Map_* / dict_* : keyed containers

A type prefix is added when it adds clarity:

  • count-of_* : number of elements
  • Bool_* : Bool type
  • flag_* : value used as a Boolean flag

For names of directories and files:

  • dir_* / dirn_* : directory name
  • dirp_* : directory path
  • dirpr_* / dirpa_* : relative / absolute directory path
  • file_* / filen_* : file name
  • filep_* : file path
  • filepr_* / fpr_* : relative file path
  • filepa_* / fpa_* : absolute file path
  • fsnodn_* : file system node name
  • fsnodp_* : file system node path
  • fsnodpr_* / fsnpr_* : relative file system node path
  • fsnodpa_* / fsnpa_* : absolute file system node path

The prefix is a component, so in a language without the hyphen its underscore is demoted with the rest: list_HTTP-server is list__HTTP_server, and dirpa_root is dirpa__root.

A predicate function is named with the prefix is_* or has_*, as is_document or has_right-neighbor. The prefix is a component too, so in Python these are is__document and has__right_neighbor.
